# Wethaq analysis scripts (Sprints 3–4)

These scripts produce the forecasting and inventory results that the dashboard shows. They are kept here so the results can be reproduced, as the proposal requires.

## Run

1. Install Python 3.11 or newer, then the packages:
   ```
   pip install -r requirements.txt
   ```
2. Run everything (about 2–3 minutes), giving the path to the `Wethaq_Datasets` folder supplied by the supervisor:
   ```
   bash run_all.sh ~/path/to/Wethaq_Datasets
   ```
3. Results are written to `out/`. They should match the reference copies in `results/`.

The datasets are not stored in this repository. The scripts read:

| File | Used for |
|---|---|
| `01_RAF_Spare_Parts_Demand/Data/RAF_long.csv` | Forecasting (real RAF demand, 5,000 parts, 1996–2002) |
| `04_Optional_Extras/A_Synthetic_Aviation_Demand_12960/obj1_synthetic_demand.csv` | Inventory simulation (synthetic panel, 60 parts × 3 locations, 2018–2023) |
| `04_Optional_Extras/A_Synthetic_Aviation_Demand_12960/generate_obj1_synthetic_demand.py` | The supervisor's generator, used for the synthetic panel's lead times and settings |

## Scripts, in run order

| Script | What it does | Main output |
|---|---|---|
| `assess.py` | Checks both datasets and classifies each series (smooth, erratic, intermittent, lumpy) | `assessment.json`, `raf_series_classes.csv` |
| `forecast.py` | Naive, MA12, SES, Croston, SBA, TSB and a global gradient-boosting model; chronological holdout; MAE, RMSE, MASE, RMSSE, bias | `forecast_results.json`, `forecast_results.xlsx` |
| `forecast_ablation_no_flight_cycles.py` | Same as above with the flight-cycle feature removed, to measure its effect | `ablation/forecast_results.json` |
| `raf_export.py` | Exports 40 RAF parts with their forecasts for the dashboard's forecasting page | `raf-forecasts.json` |
| `rolling_raf.py` | Rolling-origin evaluation of the RAF forecasts over four windows | `sprint4/raf_rolling.json` |
| `inventory_sim.py` | Monthly periodic-review simulation comparing the current policy, a fixed threshold and forecast-based reorder points (2022 warm-up, 2023 measured, z = 1.645) | `sprint4/inventory_sim.json` |

## Differences from the proposal

- **Forecasting dataset:** the proposal planned to forecast on the synthetic aviation panel. With the supervisor's approval (Option A), forecasting uses the real RAF dataset, and the synthetic panel is used for the inventory simulation.
- **Machine-learning model:** XGBoost could not be installed in the working environment, so scikit-learn's `HistGradientBoostingRegressor` (Poisson loss) is used as the gradient-boosting model.
- **Simulation:** SimPy was not available, so the inventory simulation is a direct monthly loop in Python. It models the same periodic-review, lost-sales process.
- **Shipment data:** the dashboard's demonstration shipments are generated by the application itself; the synthetic logistics dataset (folder `02_Logistics_Operations`) is not used.

All results apply only to these datasets and assumptions. The synthetic panel shows how the policies behave, not real-world savings.
