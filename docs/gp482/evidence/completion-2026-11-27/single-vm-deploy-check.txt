Single-VM deployment configuration (deploy/compose.yml) — local check on the development machine
Date: 2026-11-27 (UTC). This is NOT a cloud deployment: nothing was deployed to a hosted server and no paid
resources were created. The stack ran on the sandbox machine next to the local Fabric test network.

Setup
- Fresh Fabric test network: ./fabric/reset.sh --yes, then WETHAQ_SKIP_CC_BUILD=1 ./fabric/up.sh (exit 0;
  the chaincode image from the earlier build was reused because npm cannot reach the registry from build
  containers in this sandbox; the chaincode source is unchanged).
- API image: wethaq-api/Dockerfile built with a sandbox-only npm proxy/CA step (not committed), tagged wethaq-api:test.
- Dashboard: VITE_WETHAQ_LIVE=true npx vite build --outDir dist-live.
- deploy/production.env: scratch values generated with openssl rand (outside the repository, deleted afterwards),
  WETHAQ_SITE_ADDRESS=http://:80 published on 127.0.0.1:8088 (plain HTTP: no domain, so no certificate).
- The enrolled identities were copied to a scratch folder owned by uid 1000 (the container user).
- docker compose -f deploy/compose.yml --env-file <scratch env> config --quiet  -> OK
- docker compose ... up -d --no-build  -> postgres healthy, api healthy, web up
- bootstrap: docker compose exec api tsx src/cli/bootstrap.ts --admin-email ops@example.org
  --admin-name "Operations Admin" --demo-catalogue  -> exit 0 (temporary password printed once; not recorded here)

First attempt (finding, kept on purpose)
- Mounting the whole test-network organizations folder failed with EACCES: its folders are mode 700 and hold
  the peers' and orderers' private keys. compose.yml now mounts only the two peers' TLS CA certificates.
- Against the Fabric network that already held the development data, the new database numbered its first
  shipment SHP-2026-0001, which already existed on the ledger. The chaincode refused it ("Shipment
  SHP-2026-0001 already exists") and the API answered 502 with nothing written to PostgreSQL. A new
  installation therefore needs a new channel (or network); see DEPLOYMENT_GUIDE.md. The check was repeated on
  a fresh network.
