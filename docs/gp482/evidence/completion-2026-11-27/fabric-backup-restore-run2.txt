# NOTE (added after the run): second run of the drill. Right after backup.sh restarted the network, the API's first submission failed with '14 UNAVAILABLE: no orderers could successfully process transaction': the orderer had not yet elected its Raft leader (it took about 7 s). The API handled it as designed (Case C, unknown outcome, HTTP 202, request kept pending), but it showed that start.sh and restore.sh returned before the network could order transactions. Fixed by wait_for_orderer in fabric/lib.sh (used by start.sh and restore.sh). The network was then recreated (reset.sh, up.sh, seed --reset) and the drill run a third time: fabric-backup-restore.txt.
